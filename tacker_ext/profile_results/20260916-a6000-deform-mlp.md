## CUDA Event timing

Each entry is the median of seven rounds, with 100 launches per round and 20
warm-up launches per configuration. The profiler was not attached.

| Requested persistent blocks | Median ms | Speedup vs default |
|---:|---:|---:|
| 0 (defaults to 84) | 7.540038 | 1.000x |
| 84 | 7.537644 | 1.000x |
| 168 | 4.411482 | 1.709x |
| 336 | 3.105014 | 2.428x |
| 672 | 3.541627 | 2.129x |
| 6,971 (full grid) | 3.044639 | 2.476x |

The default one-block-per-SM grid is therefore not the best configuration for
this workload. Full-grid launch was fastest among the tested values, narrowly
ahead of 336 requested blocks.

## Paired cache-eviction timing

Each pair first touches a 64 MiB eviction buffer, measures one target launch,
and immediately measures a second launch. There were 50 pairs.

| Persistent blocks | Evicted median ms | Immediate warm median ms | Ratio |
|---:|---:|---:|---:|
| 0 | 7.547392 | 7.533056 | 1.0019x |
| 6,971 | 2.988544 | 2.981968 | 1.0022x |

Launch-start cache state changed total latency by only about 0.2% in this
experiment. This is timing evidence only; it does not identify the actual
DRAM/L2 traffic or warp-stall distribution.
